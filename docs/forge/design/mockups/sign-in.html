Sign in

Route /signin. Email + password. Any failure shows the same message (the API gives one 401 body so nothing reveals which emails exist).

Sign in: default

Password field shows the focus ring, as it would while typing.

Spec: Frontend: Auth screens > Sign in · PRD: Accounts and Sign-In

Sign in: wrong email or password (401)

One message for every failure, shown under the password and echoed in a banner for screen readers (role="alert"). Both fields take the danger border; the message has an icon, so colour is not the only signal.

Spec: Frontend: Auth screens > Sign in · PRD: Accounts and Sign-In

Sign in: too many tries (429)

Auth routes allow 5 a minute per IP. Wait copy tells people what to do; no countdown is promised because Retry-After is only a header.

Spec: Frontend: Auth screens > Sign in; Backend: Auth module (Throttling) · PRD: Accounts and Sign-In

Sign in: server unreachable
