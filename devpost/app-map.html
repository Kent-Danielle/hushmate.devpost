Hushmate: App Map

A take-home guide to where things live. It's a snapshot of the code at commit 4a04aec (2026-10-04), so it can drift as the code changes.

What it is

Hushmate is a mobile-first web app for housemates. Everyone shares their weekly quiet times. When it gets loud, you can send a housemate an anonymous nudge: a real phone notification in the app's own voice, never with your name. They tap Got it, and only you see that they did.

  • Frontend: React + Vite in frontend/, hosted on Vercel. Screens, the service worker (public/sw.js) and the time maths (src/lib/).
  • Backend: NestJS in backend/src/, on one always-on Fly.io machine. Sign-in, houses, quiet times, nudges, push, and the demo scheduler.
  • Database: Postgres on Supabase, accessed through Prisma (backend/prisma/schema.prisma).
  • Push services: Apple, Google and Mozilla deliver the notifications, signed with VAPID keys.

One action, end to end: sending a nudge

The route (three stops)

This is a reference route. Search for the quoted anchor in your editor to land on each spot.

  1. Picking someone: frontend/src/screens/schedule/NudgeSheet.tsx
    Anchor: function NudgeSheet and function NudgeRow. This lists housemates from the board, asks first if they're resting, and blocks anyone away. Tapping a row calls useSendNudge in frontend/src/api/hooks/nudges.ts, which posts to /nudges and starts the "Nudge again in m:ss" countdown.
  2. The kernel: backend/src/nudges/nudges.service.ts
    Anchor: async send(, then async createAndSend(. This checks that both people share an active house (403 if not), enforces the 5-minute cooldown (429), saves the nudge with a random message from messages.ts (NUDGE_MESSAGES), and hands it to PushService.sendToUser in backend/src/push/push.service.ts. The push payload comes from buildEnvelope in push-payload.ts and never includes the sender.
  3. Receiving it: frontend/public/sw.js and frontend/src/components/NudgeOverlay/NudgeOverlay.tsx
    Anchors: addEventListener('push' and function NudgeOverlay. The service worker shows the notification. The app finds the nudge through usePendingNudges (on open, on switch-back, and every 5 s while visible) and shows the overlay. Got it calls useAcknowledge, and the sender's Summary then lists it.

To change this, start here

  • The five nudge messages or the demo subtitle: backend/src/nudges/messages.ts
  • Nudge cooldown length: NUDGE_COOLDOWN_MS in backend/src/me/me.service.ts (the nudges service reuses it)
  • How often the open app checks for nudges or schedule changes: refetchInterval in frontend/src/api/hooks/nudges.ts and board.ts
  • Demo timing (first nudge, follow-ups, bot Got it): backend/src/me/me.service.ts (arming), backend/src/demo/demo.service.ts (BOT_ACK_DELAY_MS, next-nudge minutes), and the job table in backend/src/scheduler/scheduler.service.ts
  • Demo world (bots, quiet times, heads-ups, nightly reset): backend/src/demo/demo-data.ts
  • Welcome card and other demo copy: frontend/src/lib/copy.ts
  • Colours, type and spacing: frontend/src/styles/tokens.css
  • Quiet-time overlap maths: frontend/src/lib/quietTime.ts and backend/src/common/quietTimeOverlap.ts. Change both together; their tests mirror each other.

A practice to reuse

Plan the product in detail, then schedule early hands-on checks for the things only real devices can answer.

Every feature in this build shipped as the PRD described it. The final review only tuned demo timings and refresh rates. The surprises were platform facts no document could settle:

  • Apple rejects the Web Push Topic header. This showed up at the slice 4 two-phone check, and the fix is in push-payload.ts.
  • Desktop Safari shows declarative pushes without waking the service worker. This was already marked "needs a device check" in docs/forge/research/web-push.md, and the fix is visible-only polling.

Mocked tests passed throughout (the e2e suite mocks web-push). The device checkpoints in devpost/checklist.md > Hands-on Checkpoints caught both. On the next project, while planning, list the unknowns only hardware or a third party can answer, and put a hands-on check right after the slice that first depends on each one.

Run it again

From app/ (needs Docker / OrbStack):

./scripts/init-env.sh
docker compose up --build -d
docker compose exec backend npx prisma migrate dev
docker compose exec backend npm run seed

Then open http://localhost:5173. To stop: docker compose down (keeps data), or add -v to wipe it.

Tests 
docker compose exec backend npm test
docker compose exec backend npm run test:e2e
docker compose exec frontend npm test
cd frontend && npx playwright test
