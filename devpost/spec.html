Hushmate: how it's built

A mobile-first PWA (React on Vercel) talking to one always-on NestJS backend on Fly.io, which owns every rule, sends every push, and keeps Postgres on Supabase. No live sockets, no external schedulers. This spec is the complete architecture: implementers work from it alone. Research and sources are in docs/forge/research/.

Legend: unlabelled = your decision (including accepted research defaults) · agent detail = derived · verify early = check in build slice 1.

In plain language: three pieces and a database

1
app/frontend · Vercel

The web app

React screens on your phone. A PWA without extras: a service worker (the one script the browser keeps alive for the site, so pushes can land) and a manifest (name and icon, so iPhone can add it to the Home Screen). No offline mode, no install prompts.

2
app/backend · Fly.io

The backend API

NestJS on one always-on machine. It checks passwords and issues sign-in tokens, enforces every rule (anonymity, cooldown, demo locks), sends push notifications, and runs three timers: Demo nudges and bot acknowledgements, the 3 AM reset, and the heartbeat.

3
Supabase · Postgres

The database

Eight tables only the backend reads and writes, reached through one encrypted Session-pooler connection. Locally it's a Postgres container, so experiments never touch the live demo.

Components: every heading the build will cite

BackendNudges module, the kernelprd › Nudging · Acknowledging

Does

  • createAndSend({…, skipCooldown}): cooldown (except for bots) → random message → insert → push after the commit, without waiting
  • POST /nudges: same active house, different people; 429 with cooldownUntil
  • GET /nudges/pending: message + subtitle, never the sender; acknowledge clears everything waiting
  • No sender id or name in any payload, log line or push topic

Where it runs, provisioning, and the bill

Locally: exact commands

./scripts/init-env.sh
docker compose up --build -d
docker compose exec backend npx prisma migrate dev
docker compose exec backend npm run seed
# open http://localhost:5173 · API :3000 · Postgres :5432
docker compose exec backend npm test
docker compose exec backend npm run test:e2e
docker compose exec frontend npm test
cd frontend && npx playwright test

Rule: a local backend never uses the production database, because two schedulers would both fire.

Live: you sign in three times, the agent does the rest

You: fly auth login · supabase login · vercel login. The agent then creates the Supabase project (name and region confirmed with you) and the prisma user, launches the Fly app (--ha=false), imports secrets from git-ignored .env.production.local (never printed), deploys (migrations run as the release command), seeds once, and deploys the frontend with the Vercel CLI.
